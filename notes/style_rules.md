# Style rules applied to the article

From "Five Principles for Generating Readable AI Text in Bulk" (Shreya Shankar, Full Stack Data Lab) and the plain-writing skill.

1. Sentence order. Each heading and each list item starts with its subject, then a present-tense verb. Example: "Flash misses the mix shift on open questions."
2. Key words first. Headings and table cells lead with the word that makes them different (mode name, case name, network ID).
3. One structure, one word per concept.
   - Flash and Standard are the two mode names. "Standard" means standard Agent mode. Never "deep mode", "slow mode", "regular mode".
   - question = one of the 28 benchmark questions. request = one API call. response = what came back. conclusion = the response's final claim.
   - network = one scenario. zone = local or remote (the column is service_zone). Never "segment".
   - reversal network and control network. Never "trap", "variant", "version" in prose.
   - completion time. Never "latency", "speed", "wait" as a measure.
   - pass = all four criteria met. correct conclusion = criterion 4 met.
4. Variation only for meaning. Every case description has the same parts in the same order: check, reversal network, control network. Every result section has the same parts: claim, numbers, one example.
5. Verb connotation. Results use verbs that show direction: "catches", "misses", "ties", "takes longer".
6. Plain writing: no dashes, colons only before lists, no analogies, no filler, no bold as decoration, sentence-case headings.
